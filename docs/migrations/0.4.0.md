# Migrating to 0.4.0

This guide covers the unpublished 0.4.0 Rust API-hardening line. The packages
remain unpublished pending separate approval.

## CLI crate

The CLI package exposes only its runtime entrypoint.

```rust
// Before
use telltale_cli::cli::scan::run;

// After
use telltale_cli::run;
```

## Core facade

`telltale-core` is the supported embedding facade. Broad lower-crate aliases
and `Pipeline::rule_set()` were removed.

```rust
// Before
use telltale_core::{rules, schema, sources, CompiledRuleSet};
let rules = pipeline.rule_set();

// After
use telltale_core::{Event, NormalizedRecord, Pipeline, Source};
let events = pipeline.detect_records(&source, &records);
let matches = pipeline.evaluate_session(&records)?;
```

Use the owning crates directly when a lower-level API is intentionally needed;
the core facade does not provide duplicate lower-crate namespaces.

## Canonical schema ownership

Shared schema types are owned by `telltale-schema`, not re-exported through
duplicate source modules.

```rust
// Before
use telltale_sources::{
    clients::{ClientId, SourceKind},
    discovery::Source,
    parser::{NormalizedRecord, RecordKind},
};

// After
use telltale_schema::{
    clients::{ClientId, SourceKind},
    record::{NormalizedRecord, RecordKind},
    source::Source,
};
```

## Lightweight detection

`telltale-detect` enables source I/O by default. Consumers that already have
normalized records can avoid source discovery, SQLite, and `walkdir`:

```toml
[dependencies]
telltale-detect = { version = "0.4.0", default-features = false }
telltale-rules = "0.4.0"
telltale-schema = "0.4.0"
```

In this mode, use in-memory APIs such as
`detect_parsed_source_records`, `evaluate_session_matches`, and baseline or
timeline helpers. Filesystem-backed detection and MCP inventory helpers require
the default `source-io` feature.

## Checked and best-effort discovery

Checked discovery now returns structured errors. Existing CLI-style behavior is
available through explicitly named best-effort helpers.

```rust
// Before
let sources = telltale_sources::discovery::discover_sources(root);

// After: invalid roots and traversal failures are reported
let sources = telltale_sources::discovery::discover_sources(root)?;

// Preserve partial/empty best-effort behavior when that is intentional
let sources = telltale_sources::discovery::discover_sources_best_effort(root);
```

The same checked/best-effort distinction applies to
`discover_sources_with_projects` and its `_best_effort` counterpart.

## Validated risk contributions

`RiskContribution` fields are no longer directly constructible. Use the
validated constructor and getters.

```rust
// Before
let points = contribution.points;

// After
let contribution = RiskContribution::new(
    "rule.example",
    RiskContributionType::DeterministicRule,
    10,
    "example rule",
)?;
let points = contribution.points();
let id = contribution.id();
let kind = contribution.contribution_type();
let rationale = contribution.rationale();
```

`RiskAccountingError`, `DiscoveryError`, and `ParseError` are also
non-exhaustive.

## Non-exhaustive public enums

`ClientId`, `SourceKind`, `RecordKind`, `PathRoot`, and `SourcePattern` are
non-exhaustive. Downstream matches must include a wildcard arm:

```rust
match client_id {
    ClientId::Codex => handle_codex(),
    _ => handle_other_client(),
}
```

Do not add a wildcard arm solely to matches inside the defining crate; those
matches remain exhaustive until a new variant is actually added.

## Source and record boundaries

Runtime registration of custom clients, discovery roots, or source parsers is
not supported. An arbitrary string in `NormalizedRecord.client` only labels a
caller-supplied record; it does not add discovery or parser support. New source
support requires a bundled registry/parser implementation.

## Unchanged behavior

- Event schema 2.0 and emitted event shape remain unchanged.
- CLI flags, defaults, output, exit status, and both `telltale` and `adr`
  binaries remain unchanged; `adr` remains the retained compatibility command.
- Rules, parsing, scoring, redaction, source ordering, sinks, retries, and
  delivery behavior remain unchanged.
- No package is published by this migration. Publication requires separate
  approval and the documented dependency-ordered process.
