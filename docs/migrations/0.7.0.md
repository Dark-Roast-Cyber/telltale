# Migrating to 0.7.0

Status: compatibility guide for the 0.7.0 release candidates. The latest
published prerelease is `v0.7.0-rc.2`; stable `v0.7.0` is not published.
Candidate identities and qualification results are on each
[GitHub Release](https://github.com/Dark-Roast-Cyber/telltale/releases).

`v0.7.0-rc.2` adds bounded OpenCode tool-result
and patch text and less redundant evaluation work; see
[OpenCode ingestion limits](../opencode-live-ingestion.md). Event3, state format,
stable identities, and the newest-5,000 bootstrap coverage are unchanged.

## Rust embedding changes since RC1

Everything in this section is in the published `v0.7.0-rc.2` prerelease, not
the RC1 artifacts. Update your Git pin deliberately and revalidate
the host; RC1 evidence does not qualify these changes. The resulting contract is
in [embedding](../embedding.md); hosts adopting actions should start at
[detailed action scanning](../embedding.md#detailed-action-scanning).

**Errors.** `build` and the `scan_*` methods return the
non-exhaustive `telltale_core::PipelineError` instead of boxed errors. Replace
downcast-based classification with enum matching plus a fallback arm. Functions
returning `Box<dyn Error>` can still use `?`, but explicitly forwarded boxed
results must convert, for example `Ok(pipeline.scan_root(root)?)`. Missing
documents are `InvalidConfiguration`; `Compilation` has an opaque diagnostic
source. Rule content that loads as Rule v1 but that canonical compilation
rejects (for example an unknown severity or a score above 100) now fails
`build()`; it no longer builds a `Pipeline` whose scans all return
`Compilation`. Content and policy that leave no effective rule now fail with
`EmptyRuleSet` instead of building a pipeline with no Rule v1 rules. This
applies even when later scans would enable `process_chain`, whose bundled
process-chain rules are separate and could still detect. See [typed pipeline errors](../embedding.md#typed-pipeline-errors).

**New scan methods.** `scan_sources` scans exactly the supplied sources (RC1
adopters only have `scan_root`). `scan_*_with_occurrences` add observation
linkage. `scan_*_detailed` is the action API.

**Source outcome.** Use `SourceScan::failure()` instead of matching
`scanner_error` strings or inferring failure from `completion.is_none()`.
`coverage()` reports `WholeSource` or `Partial` (OpenCode).
`visibility_limits()` names the reasons for `VisibilityLimited`. Default bundled
scans of timed, session-scoped sources are now `Complete` when no other
visibility limit applies (for example an unverified source instance or a
detector that could not evaluate its input): the Rule v1 `url`
target reads URL-keyed tool arguments instead of being unavailable, and the
`RuleTargetUnavailable` limit is removed. Session Event 3 can gain `url`
evidence for rules that target it. See
[Rule v1 URL target](../embedding.md#rule-v1-url-target).

**Action findings.**
- `session_event_index()` links an action to the Event 3 event projected for it
  (the session Rule v1 detection when it carries every rule of the action, or
  the process-chain event from the same result). Replace session-ID matching
  with it; handle `None`.
- Action DTOs no longer implement `Serialize`. Project accessors into a
  host-owned versioned envelope; compare with `==` (`Eq`) and inspect with
  `Debug`. The same applies to `RuleCatalogEntry`/`RuleCatalogKind` and to the
  unstable investigation `OccurrenceContext`/`ContextEntry`.
- `stage()` is `ObservationStage`, `kind()` is `ObservationFamily`, `severity()`
  (also on `CanonicalActionFinding`) is `Severity`, and `ActionContextEntry::kind()`
  is `ActionContextKind` with a new `stage()`. Use `as_str()` for the unchanged
  labels.
- `score()` is removed; use `promotion_score()`. It is neither native finding
  risk nor the Event 3 session score.
- Action and context `tool_name()` keep known built-in harness names readable
  (for example `Bash`); Event 3 is unchanged. Hosts that validated action tool
  labels with `terminal_historical_identifier("tool", …)` must switch to
  `terminal_historical_tool_label`, which accepts readable built-in names.

**Pipeline reuse.** `build()` compiles canonical semantics once; keep one
`Pipeline` rather than rebuilding per scan. A canonical rejection is now a
`build()` error rather than a later scan error.

**Acquisition errors.** `AcquisitionError`, `BoundedReadError`, and
`CanonicalBoundContext` are re-exported from core. New variants
`CanonicalBoundValidation { context }` (Codex bound failures) and
`CapabilityNotCompiled` (OpenCode without `opencode-sqlite`, previously
`SourceRead`) break exhaustive matches; add arms or a wildcard. A resumed
OpenCode read over its part limit reports `BoundedSourceRead(LimitExceeded)`
instead of `SourceRead`. `AcquisitionError` is now `#[non_exhaustive]`, so
matches need a wildcard arm. Its new `ResumeRegressed` variant reports a resumed
OpenCode read against a store with no part at or after the token. Resume tokens
now bind the exact source path bytes, so tokens persisted by earlier unreleased
builds return `InvalidResumeToken`; scan without one. `OpenCodeSqliteReadOptions`
(`telltale-sources`) gained the public `resume_high_water` field, which breaks
struct literals; use `..Default::default()`. `OpenCodeSqliteReadOptions::resume_after`
sets it, so direct callers of that helper, and the CLI cursor, now get
`ResumeRegressed` for a regressed store instead of an empty read.
`ObservationError` also exposes optional typed bound dimension/context; its
Display is unchanged. Event 3 adaptation stays generic.

**OpenCode feature.** The default core dependency graph no longer includes
`rusqlite`; enable `opencode-sqlite` to scan OpenCode. The CLI enables it.
See [OpenCode acquisition](../embedding.md#opencode-acquisition).

**Resuming OpenCode.** `scan_source_detailed_resuming` with a persisted
`ResumeToken` (from `SourceScan::resume_token()`) reads only parts updated since
the prior scan, with the CLI's overlap and limit. Hosts that rescanned the
bounded recent window on every change can switch; see
[resuming OpenCode scans](../embedding.md#resuming-opencode-scans).

**Record evaluation removed.** `Pipeline::detect_records`,
`Pipeline::evaluate_session`, the `telltale_detect::detection` module, and the
core re-exports of `NormalizedRecord`, `RecordKind`, `MatchResult`, and
`RiskAccountingError` are removed. They evaluated flattened records with Rule v1
outside the canonical path. Write a native session fixture (for example Codex
JSONL) and use `scan_sources_detailed`; see
[removed record evaluation](../embedding.md#removed-record-evaluation).

**Opt-in additions.** `telltale_core::inventory` (no rule compilation, no MCP
connection, no scan/watch emission) and
`SessionInvestigator::investigate_context` (content off by default, OpenCode
deferred) require no persistence migration.

These changes preserve the Event 3 schema, already-persisted Event 3 bytes,
state formats, CLI exit semantics, and rule validation order. Newly emitted URL
evidence can differ as described above. CLI diagnostics are unchanged except
one: an incremental OpenCode read over its part limit reports the scan summary
failure `acquisition_code` `source_limit_exceeded` instead of `source_read`.
The Event 3 `scanner_error` event for that failure is unchanged.

## OpenCode v2 changes after RC2

These changes are not in the published `v0.7.0-rc.2` prerelease; they apply
to a later candidate. Update your Git pin deliberately and revalidate the host.

OpenCode v2 (`session_message`) stores add `AcquisitionProgress::OpenCodeSessionMessages`,
which breaks exhaustive matches on `AcquisitionProgress`; keep it separate from
part progress. `OpenCodeSqliteReadOptions` gained `message_*` fields and
`resume_session_messages_after`, and `AcquisitionError::UnsupportedSourceSchema`
reports an incomplete v2 schema. Existing legacy resume tokens still parse.
`AcquisitionProgress::OpenCodeSessionMessages` gained `window_complete`. A v2
read that exceeds its row limit or the retained budget now returns a cut
window instead of `LimitExceeded`; only a single `time_updated` group that
alone fills a window still fails as `LimitExceeded`, because a window ends on
a whole group. After a cut, continue with
`OpenCodeSqliteReadOptions::continue_session_messages_after`; once a window
completes, resume with `resume_session_messages_after`.
`OpenCodeSqliteReadOptions` also gained `message_window_bytes`. Embedding
resume tokens now issue
`session_message_window:<checkpoint>:<cut>:<binding>` after a cut, under the
existing `resume:v1:opencode.sqlite:` prefix. CLI state cursors retain the optional
`draining` flag and add `continue_after_time_updated` while a backlog drains.
The checkpoint stays monotone; strict continuation uses the raw cut even below
that checkpoint. `continue_session_messages_after` now preserves any higher
`message_resume_high_water` regression floor already in the read options.
Older complete tokens/state remain unchanged. Older `session_message_drain:`
tokens and `draining` state without a raw cut remain accepted, but resume by
replaying the checkpoint's ten-minute overlap, then issue the new format. This
can repeat evaluated rows; it cannot recover already-skipped rows outside that
overlap. A separately selected history scan is needed to inspect those rows.
Older builds reject the new token coordinate or unknown cursor field, rather
than silently skip unfinished overlap. Do not strip `continue_after_time_updated`
while leaving `draining: true`, or rewrite a `session_message_window:` token into
an older `session_message_drain:` token containing only the checkpoint: older
readers then continue strictly after the checkpoint and can skip unfinished
overlap. Finish the drain with the new reader before downgrading, or restore a
coordinated earlier source/state/token snapshot and its matching accepted output.
Dropping the token and bootstrapping is not an overlap-safe rollback, even if an
older reader rejects the new token. Explicit state relocation preserves both
coordinates.
An explicit [operator cursor reset](../opencode-live-ingestion.md#explicit-operator-cursor-reset)
can now discard one exact stored OpenCode source/schema cursor without changing
baselines, deduplication or other progress. This is intentionally lossy maintenance,
not a state-format migration or safe rollback. Pause scanners, inspect the cursor
and supply its matching digest plus history-gap acceptance; abandoning an
unfinished drain needs a separate acknowledgement. The next scan selecting that
schema attempts bounded bootstrap only. Surviving raw-cut fields and older-reader
rejection remain unchanged.
`AcquisitionBatch` gained `quarantined: Vec<QuarantinedUnit>`, which breaks
struct literals, and `SourceScan` gained `quarantined()`. An OpenCode v2 row
with an oversized or invalid value, or one whose smallest window exceeds
evaluation capacity, is now quarantined and reported by coordinates instead
of failing the source. The stdout scan summary adds
`source_processing.quarantined_unit_count` and `quarantined_units`.
`AcquisitionBatch` also gained `message_overlap_from` and `SourceResult`
(`canonical_runtime`) gained `window_bytes` and `message_overlap_from`, which
break struct literals. `OpenCodeSqliteReadOptions::session_message_history`
selects a v2 store from its earliest message. A row whose stored payload
exceeds the 8 MiB read cell limit is quarantined as `oversized_native_cell`
instead of failing the source. The CLI drains a v2 backlog in up to 64
overlapping windows per scan, reports `evaluated_window_count`, and adds
`scan --history all` for a forensic pass that never touches scan state.

## Embedding hosts: changes after RC2

These are not in the published `v0.7.0-rc.2` prerelease. A host that embeds
`telltale-core` and moves its pin past RC2 should check each item; CLI,
installer and release-tooling changes are listed in the changelog only.

- **Wire forms.** `SourceScan::action_records()` returns versioned
  `ActionRecordV1` values and `rule_catalog_document` returns `RuleCatalogV1`;
  both have strict consumers in `telltale-schema` and JSON Schemas in
  `schemas/`. They replace host-designed action and catalog formats; see
  [host wire](../embedding.md#host-wire-and-durable-handoff). Additive.
  Key deliveries with `ActionRecordV1::delivery_key()` and check the event
  that travels with a record with `check_session_event`. A key built from
  `source_path_hash` and `coordinate` alone merges the several process-chain
  actions one tool call can carry.
- **Action record v1 and rule catalog v1 amended before their first tag.**
  Neither format has been in a tag yet, so 0.7.0 ships one complete v1
  rather than a v1 and a v2; each is frozen from the first release tag that
  carries it. A Git pin past RC2 can hold an earlier v1: its consumers
  reject the amended output (missing or unknown fields), so move producer and
  consumer pins together. The amendments:
  - Evidence locates its hit. Each evidence entry has required `highlight`
    (`{start, end}` UTF-8 byte range in `redacted_value`, or null),
    `elided_before` and `elided_after`. A field longer than the evidence
    bounds is now an excerpt around the hit that counted instead of its first
    512 bytes, so the same input can yield different `redacted_value` text in
    action records, and it can be empty when only text near a cut remains;
    Event 3 evidence is unchanged. `from_json` rejects a
    highlight that is empty, reversed, out of range or off a character
    boundary. See [evidence](../embedding.md#evidence).
  - Catalog entries have required `attack_techniques`, and with
    `process_chain` enabled the catalog lists the bundled process-chain rules
    as kind `process_chain`. `RuleCatalogKind` gained `ProcessChain`; it is
    `non_exhaustive`, so matches already need a wildcard arm.
  - `ActionRecordEvidence` and `RuleCatalogEntryV1` gained fields, which
    breaks struct literals. `ActionRecordHighlight` and
    `ACTION_RECORD_MAX_INPUT_BYTES` are re-exported from `telltale-core`.
- **Delivery aliases.** `ActionRecordV1::delivery_aliases()` returns
  `delivery_key()` and, with a replay identity, the source-bound key the
  action has without one. An action's replay identity is withdrawn when a
  later identical candidate makes it ambiguous, which changes its
  `delivery_key()`. Treat an action as handled when any alias is known and
  remember all of them; see
  [host wire](../embedding.md#host-wire-and-durable-handoff). Additive.
- **Semantic identity changes.** The embedded `telltale.community` package is
  on by default (`tdx.*` rules; catalog entries carry `package_id`;
  `without_community_rules()` opts out). New rule
  `prompt_injection.instruction_override` and modifier
  `chain.instruction_override_with_approval_bypass`, the approval-bypass
  exclusion fix and the Codex completed-command view change results for the
  same input. Expect a new `semantic_provenance` identity: run the host's
  rebaseline and keep admitted pending work. The embedded package is now
  `telltale.community` 0.1.1: three new Windows persistence rules and revised
  patterns for three existing `tdx.*` rules also change results for the same
  input.
- **Bundled detections that follow what a command does.** Native action
  profile 4, the `written_path` rule target, destructive commands scoring as
  alerts, `chain.secret_then_network` requiring an upload, the removal of
  `chain.install_then_persistence` and declared chain links also change results
  for the same input; rebaseline as above. A modifier may declare `link`; one
  without keeps session-wide co-occurrence. `ModifierDefinition` and
  `RuleV1CompatibilityModifier` gained `link` and `ActionModifierSemantics`
  gained `within_calls`, which break struct literals. `SelectorId` gained
  `CompatWrittenPath`, which breaks exhaustive matches.
- **Sanitizer keeps command flags and plain identifiers.** Redacted text keeps
  a bare `/word` of 1-16 characters from `[A-Za-z0-9_-]` (`cmd.exe /c`,
  `schtasks /create /tn`, and also a bare `/etc`) and a mixed-case run with
  fewer than two digits and no `+`, `/` or `=` (`ContosoDetectionTest`,
  `New-ScheduledTaskTrigger`), so Windows command evidence stays reviewable.
  Paths with more shape, drive and UNC paths, secrets, credentialed URLs and
  encoded-looking runs are masked as before; see the
  [privacy model](../privacy-model.md). The same input now yields different
  `redacted_value` text in Event 3 and action records. `Event3Record` applies
  no redaction fixed-point check, so Event 3 consumers are unaffected. An
  `ActionRecordV1::from_json` consumer built from an earlier `main` rejects the
  new text, because redaction would still change it: Git-pinned consumers must
  move producer and consumer together. Any later loosening of the sanitizer
  has the same effect on older v1 consumers.
- **Sources that used to fail now parse.** Current Claude Code 2.1.x
  transcripts and current Codex rollouts previously failed as whole sources.
  The first scan after the upgrade returns their history; the host's backfill
  and rebaseline policy decides what is delivered.
- **Large single sources.** Per-source bounds of JSONL session sources now
  scale with the bytes read and stop growing at 64 MiB; see
  [source size](../embedding.md#source-size). A session file of more than a few MiB
  (about 3 MiB in synthetic tests) used to fail as
  `canonical_evaluation_failed` and now returns its findings, so the first scan
  after the upgrade can return its history. Peak RSS is about 15 times the
  source size.
- **Event 3 evidence omission.** A session detection event whose evidence would
  exceed 1 MiB used to fail the source at projection. It now keeps every
  timeline anchor and its earliest evidence, and adds one evidence item per rule
  that lost evidence, with `field` `evidence_omitted`, the omitted item count as
  `redacted_value`, the `rule_id`, and no hash. The schema is unchanged and
  events that fit are byte-identical. Consumers that enumerate evidence fields
  or expect a hash on every detection evidence item must accept it.
- **Per-unit quarantine.** Claude Code, Codex and OpenCode v2 exclude an
  unsupported or oversized unit by itself instead of failing the source:
  `SourceScan::quarantined()` lists coordinates without content and
  `coverage()` is `Partial`. Report both as health; neither is a failure.
- **OpenCode v2.** `session_message` stores are read, with new resume-token
  forms; see [OpenCode v2 changes after RC2](#opencode-v2-changes-after-rc2).
- **Stricter rule content at `build()`.** Unsupported detection severities and
  YAML-escaped control or hidden formatting characters in rule packages are
  rejected. Validate distributed content before rollout; on `Err`, keep the
  active pipeline.
- **Explicit roots ignore `CLAUDE_CONFIG_DIR`.** Environment-resolved discovery
  adds `$CLAUDE_CONFIG_DIR/projects`; discovery from an explicit root does not
  read the scanner's environment, so relocated Claude stores need their own
  source or root.
- **MCP servers.** Use `inventory::collect_mcp_inventory` for structured MCP
  inventory without `telltale-detect`: explicit files or fixed paths, sanitized
  observations, and a `reason` for named configs it cannot read or parse (see
  the limits in `docs/embedding.md`). The re-exported
  `inventory::discover_mcp_inventory_servers` is a compatibility helper: it
  walks workspace configurations, returns host-local paths, and drops configs
  it cannot read.
- **Dependencies.** `serde_yaml` is replaced by `yaml_serde` (same import
  surface). `rusqlite =0.32.1` and SQLx 0.8.6 coexistence are unchanged.
- **Rust.** The embedding crates require `rust-version = "1.88"`, checked on
  Rust 1.88.0 on Linux, macOS and Windows. This supersedes the unpublished 1.85
  declaration so dependency graphs can use patched `time` releases (`>=0.3.47`)
  for GHSA-r6v5-fh4h-64xc. Hosts on Rust 1.85 must upgrade their compiler before
  adopting this source revision.
  Hosts on Rust older than current stable should keep Cargo's
  `incompatible-rust-versions = "fallback"` resolution.

## What stays compatible

Event3 remains the production event/output contract for 0.7. Beside it,
action record v1 (`telltale.action.v1`) and rule catalog v1
(`telltale.rule_catalog.v1`) are the embedding wire forms for hosts that carry
action findings and rule metadata across a process boundary. The Event3
schema, consumer contract, terminal privacy boundary, event identity rules,
canonical JSONL behavior, and already-persisted Event3 bytes remain supported.
Action record v1 is transitional: a later release plans to supersede it with
Event 4.0 alert records that keep its delivery identity, and v1 remains
available for at least one minor release after they ship. See
[host wire and durable handoff](../embedding.md#host-wire-and-durable-handoff).

Existing non-Rust adopters should continue to consume canonical Event3 JSONL
rather than scrape scan diagnostics from stdout. Rust consumers can use
`telltale_schema::event::Event3Record` for one terminal Event3 object or
`telltale_core::LocalEventFeed` for bounded read-only local journal polling.

Rule v1 remains the supported content-compatibility format. Event4 is not a 0.7
production output and does not require an adopter migration.

## Production runtime change

The normal source-backed production path is now:

```text
source discovery
-> telltale_sources::acquisition
-> source-native extraction and native accounting/progress
-> Canonical Observation v2
-> Detection v2 (Rule v1 content and process-chain evaluation)
-> Event3 compatibility projection
-> output/durability/delivery
```

CLI scan/watch and every `telltale_core::Pipeline` scan method use that
canonical runtime.
Newly generated detections, evidence, hashes, or severity are
not required to be byte-identical to output from the retired legacy internal
runtime, even though the Event3 wire contract remains compatible.

The caller-provided record APIs `Pipeline::detect_records` and
`Pipeline::evaluate_session` are removed; see
[Rust embedding changes since RC1](#rust-embedding-changes-since-rc1).

## Supported source denominator

The 0.7 built-in source denominator is eight exact identities across six agent
families:

- Claude Code: `claude.projects`
- Codex: `codex.sessions`, `codex.archived_sessions`,
  `codex.headless_sessions`
- OpenCode: `opencode.sqlite`
- OpenClaw: `openclaw.agents`
- Qwen CLI: `qwen.projects`
- GitHub Copilot: `copilot.process_log`

The canonical [Source Validation Matrix](../source-validation-matrix.md) records
fixture and bounded live-validation status. Fixture-only source families remain
preview/experimental for live source-store use unless later qualified.

Qwen Code current-format compatibility and live-store qualification are
deferred beyond 0.7. The existing
`qwen.projects` adapter and conformance tests remain; the known text/tool/system
gaps are not repaired or qualified by this decision. See the
[Qwen compatibility boundary](../source-validation-matrix.md#qwen-code-compatibility-boundary).
The eight-identity registry is unchanged.

Current OpenClaw SQLite-store support and live-store qualification are also
deferred beyond 0.7. The registered `openclaw.agents` JSONL adapter and its
fixture checks remain, but the pinned current OpenClaw release writes runtime
transcripts to a default SQLite store that Telltale does not discover. See the
[OpenClaw compatibility boundary](../source-validation-matrix.md#openclaw-compatibility-boundary).
Neither deferral changes the built-in denominator or qualifies a live source.

The following former source identities are retired and are not built-in
discovery/parser compatibility paths in 0.7:

- `gemini.tmp`
- `opencode.legacy_json`
- `opencode.project_json`
- `roocode.tasks`
- `kilocode.tasks`
- `codex.project_sessions`

Do not depend on those identities returning as aliases. Adding one back requires
a separately accepted source contract.

## Removed transitional source APIs

Source-backed legacy record projection and parser-registration machinery was
removed after canonical runtime activation. There is no production
Canonical-Observation-to-NormalizedRecord bridge and no source-backed
NormalizedRecord-to-canonical bridge.

The direct-record APIs that evaluated caller-supplied `NormalizedRecord` values
are removed too. Source integrations should target the documented
acquisition/embedding boundary instead of retired parser registrations,
source-backed flat-record projections, or record evaluation.

### Downstream Rust integrations

Event3 JSON consumers remain compatible. Rust source integrations should use the
`Pipeline` scan methods, not retired `parser::parse_source_records` APIs.
Adopters pinned to published RC1 have only `scan_root`. Event3 projections stay
session-scoped with `timeline_anchors`; per-action results come from detailed
scans.

A vendored or modified subtree can differ in dependencies, per-action event
handling, and scoring. Do not assume drop-in compatibility with upstream 0.7.
Consumer-defined occurrence scores are not upstream scoring semantics; re-test
integrations when updating pins. Telltale remains standalone and has no
downstream-consumer dependency.

## Bounded message evaluation APIs

This applies to development builds containing Issue 79, not the immutable
`v0.7.0-rc.1` artifacts. The standalone matcher and selector APIs are now fallible:

```rust
// CompiledMatcher
pub fn evaluate(
    &self,
    observation: &CanonicalObservationV2,
) -> Result<MatcherEvaluation, ProcessingError>;

// SelectorRegistry
pub fn resolve(
    &self,
    selector: SelectorId,
    observation: &CanonicalObservationV2,
) -> Result<SelectorResolution, ProcessingError>;
```

These types are exported from `telltale_detect::v2`, except
`CanonicalObservationV2` from `telltale_schema::observation`. Update direct callers
to propagate or explicitly handle the error before using `state()`, `value()` or
`presence()`. For example, in a function returning `Result<_, ProcessingError>`:

```rust
let resolution = registry.resolve(selector, &observation)?;
let evaluation = matcher.evaluate(&observation)?;
```

Do not convert exhaustion into absence or no-match. Valid canonical observations
can carry independently governed metadata beyond the semantic/local retention
budget, so selector resolution cannot promise infallibility. Standalone detector
evaluation keeps its existing `DetectorResult` signature and reports exhaustion
as `DetectorError`; source evaluation remains all-or-nothing.

The source work counter (256 MiB, scaled for JSONL session sources; see
[source size](../embedding.md#source-size)) is independent of compatibility
retention bounds.
When sharing `EvaluationWorkBudget` for diagnostic policy comparison, use
`is_exhausted()` to distinguish true work exhaustion from other
`ProcessingError::Bounds` failures. Only true work exhaustion discards an otherwise
successful authoritative source evaluation; other comparison failures remain
diagnostic. Event3 output and inference acquisition limits remain unchanged.

## Event and telemetry boundary

Event3 remains frozen and current for production output. Event4 4.0 types,
structural schema, validation, and canonical encoding exist only as a
non-production foundation in `telltale-schema`.

0.7 does not activate:

- Event4 runtime output
- Event3/Event4 dual emission
- runtime telemetry profiles
- generalized multi-schema `CanonicalPayload`
- a generic collector or public IPC transport

A future Event4 production path must project independently from accepted semantic
truth and satisfy explicit activation gates; it must not be introduced as an
Event3 conversion layer.

## Upgrade and rollback

Review [controlled development deployment](../controlled-deployment.md) for
backup and rollback. Its development-archive installer rejects RC package
versions; do not use it to install `0.7.0-rc.1`. Published candidate
qualification must use the exact Release artifacts and their recorded release
gates. Treat configuration, scanner
state, canonical JSONL, and optional durable-delivery state as a coordinated
upgrade/rollback set.

Development builds containing Issue 69 HEC response validation add outbox error
classes that older binaries cannot decode. Before adopting that change, follow
the [durable snapshot and rollback boundary](../telemetry-output.md#delivery-guarantees)
in Telemetry output; replacing only the binary is not a safe downgrade after
new delivery classifications have been persisted. This is a development change,
not a claim about the immutable `v0.7.0-rc.1` artifacts described above.

The current stable release is `v0.6.0` until a later stable GitHub Release is
published. An RC is immutable validation evidence, not a replacement for stable
release provenance.
